# 情侣绑定与物品账本

`onetwonono` 在原有情侣活动抽卡之外，增加了一套双方共享、按账号分别计数的物品账本。

## 使用流程

1. 管理员先创建两个普通用户账号；管理员账号本身不能进入玩家功能。
2. 第一位用户登录后打开底部的“账本”，点击“创建我们的账本”。系统会自动创建一个“爱爱卡”物品，并显示 8 位邀请码。
3. 将邀请码发给伴侣。伴侣使用自己的账号登录，在“账本”中输入邀请码，即可完成绑定。
4. 绑定后，双方都能看到每种物品在两个人名下的余额，以及相同的获取/使用流水。

## 账本功能

- 默认物品：新建情侣关系时自动添加“爱爱卡”，单位为“张”。
- 自定义物品：可以设置名称、单位、Emoji 图标和说明，例如“拥抱券”“约会币”“免洗碗券”。
- 双方余额：每种物品分别显示两名成员拥有的数量。
- 获取与使用：双方都可以为自己或伴侣登记数量和备注。
- 防止负数：使用数量超过现有余额时，服务器会拒绝操作。
- 完整流水：记录物品、数量、影响的成员、实际操作者、备注和时间。
- 归档：物品归档后不再出现在余额区，但历史流水仍然保留。
- 更换邀请码：伴侣加入前可以让旧邀请码立即失效并生成新码。
- 解除绑定：任意一方确认解除后，双方都会解除绑定，该情侣关系的余额和流水会一起删除。这样后续绑定的新伴侣不会看到上一段关系的数据。

## 数据与安全边界

- 每个普通用户最多加入一个情侣关系，每个情侣关系最多两人。
- 所有接口都要求登录，写操作还会校验 CSRF；演示账号不能创建或修改账本。
- 用户只能访问自己所在情侣关系的数据，不能通过物品 ID 或成员 ID 越权访问其他情侣的数据。
- 邀请码使用去除易混淆字符的随机 8 位大写字母/数字组合；加入接口有单独的速率限制。
- SQLite 中的余额不单独存储，而是由不可变的增减流水求和得到，避免余额与历史不一致。

## 主要接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/ledger` | 获取情侣、物品余额和最近 200 条流水 |
| `POST` | `/api/couple` | 创建情侣关系和默认爱爱卡 |
| `POST` | `/api/couple/join` | 使用邀请码绑定 |
| `POST` | `/api/couple/invite/rotate` | 更换邀请码 |
| `DELETE` | `/api/couple` | 当前用户解除绑定 |
| `POST` | `/api/ledger/items` | 添加自定义物品 |
| `PATCH` | `/api/ledger/items/:itemId` | 编辑物品 |
| `DELETE` | `/api/ledger/items/:itemId` | 归档物品 |
| `POST` | `/api/ledger/transactions` | 登记获取或使用 |

数据库表由 `server/migrations/007_couple_ledger.sql` 创建。部署已有数据库时无需手工执行 SQL，服务启动会自动应用迁移。
